# KH PTZ Control 1.2.2

Status: prepared release candidate for operator testing, not a stable release.
Prepared on 2026-11-14. Physical target-Pi acceptance remains pending.
This document does not authorize an installation or certify camera behavior.

## Changes since 1.2.1

- After the last pending absolute-zoom command settles, request observed zoom
  rather than retaining only the requested target. This includes failed commands
  and exceptions, which may have left the lens at a different position (#321).
- Do not let an older readback replace a newer slider intent, including a return
  to the same requested value. Keep session, camera-selection and shutdown guards.
- Keep one command in flight and only the latest pending zoom intent. Read once
  after that queue settles; no periodic camera polling was added.

All changes already integrated in v1.2.1 are retained. The v1.2.1 tag and published
assets must remain unchanged; this candidate has its own version identity.

## Known limits and exclusions

- Last-preset priority is NOT implemented in the active controller path. If a
  preset is awaiting completion, later preset requests remain FIFO; intermediate
  requests are not discarded. This release does not promise immediate redirection
  while a camera is moving, nor physical cancellation of an earlier recall.
- The new feedback is a camera observation, not a guarantee of mechanical arrival.
  If the camera does not answer an inquiry, the actual percentage is not known.
  Continuous synchronization with an external remote is not implemented.
- Physical camera movement, interruption, stopping, touchscreen behavior and
  target-Pi installation/rollback are still pending operator validation.
- Existing ATEM/PiP and installation limits in `1.2.1.md` continue to apply.

## Pre-update and acceptance checks

1. Establish the real installed ref, launch path and GUI mode. A version label
   alone does not prove the source commit or installation layout.
2. Close the app cleanly and retain verified installation/configuration/data
   backups off the Pi before changing anything. The installer does not create a
   pre-update backup automatically. A data ZIP is not a complete SD-card image.
3. Verify the exact reviewed release commit, package contents and SHA-256. Keep
   the previous known-good installation and its supported recovery route.
4. With the operator present and outside live use, test both camera selections,
   successful and failed zoom adjustments, rapid new slider intents and session
   changes. Compare the actual lens state with the displayed ring and percentage.
5. Repeat the relevant physical checks and soak described in `1.2.1.md` and
   `../SOAK_TEST.md`. Software regression checks are not hardware acceptance.
